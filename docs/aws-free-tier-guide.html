Shifa OMS on AWS — Free-Tier Setup Guide

Written for a first-time AWS user. Copy-paste steps · EC2 + RDS · 50 concurrent users · stay free · optional Lambda automation

This guide gets the Shifa Order Management System running on AWS the safe, cheap way. You'll set up spending protection first, then a managed database (RDS), then the app server (EC2). No prior AWS experience assumed — every click and command is spelled out. If a word is unfamiliar, check the glossary.

The honest summary (read this).
  • Cost: Effectively ₹0 for the first ~12 months using the free tier + your $100 sign-up credits. After that, roughly ₹1,300–₹2,700/month. (Details in the Cost section.)
  • 50 concurrent users: Handled fine by 1 app server (EC2 t4g.small) + 1 managed database (RDS db.t4g.micro) with the connection-pool setting in Part B.
  • Trade-off to accept: Staying strictly free means one app server. During an app update there's a ~30–60 second pause. True "zero downtime" needs a paid 2-server setup — see Upgrading later. For an internal team of 50, the free single-server setup is normally fine.
  • Lambda: Optional automation (auto-backups, scheduled tasks) covered in Part D — it's essentially free.

📖 Plain-English glossary

EC2A virtual computer in AWS. This runs your app. We use t4g.small (2 CPU / 2 GB) — free.
RDSA managed database. AWS runs MySQL for you (backups, patching). We use db.t4g.micro — free for 12 months.
RegionThe city your servers live in. Use Mumbai (ap-south-1) for India.
Security GroupA firewall. It decides which ports (doors) are open. We open 22 (SSH), 80 (web), 443 (secure web).
Key pair (.pem)A password-file to log into the server. Download it once and keep it safe.
Elastic IPA fixed internet address for your server so the link never changes.
VPC / subnetYour private network in AWS. EC2 and RDS sit inside it and talk privately.
SSHThe way you log into the server from your PC (a secure remote terminal).
NginxThe web server that shows the app to users and forwards /api calls to the app.
LambdaRun a small script on a schedule without a server. We use it (optionally) for auto-backups.
Budget / Free-tier alertEmails AWS sends you if you're about to spend money. We turn these on first.

0 Turn on spending protection FIRST

Before creating any server, set up alarms so you can never be surprised by a bill. Do all three:

a) Zero-spend budget alert

  1. Top search bar → type Billing → open Billing and Cost Management.
  2. Left menu → Budgets → Create budget.
  3. Choose the template "Zero spend budget" → enter your email → Create.

Now AWS emails you the instant any real (non-free) charge appears.

b) Free-tier usage alerts

  1. Billing → Billing preferences → tick "Receive AWS Free Tier alerts" → add your email → Save.

c) A small safety budget (optional but nice)

Create a second budget of, say, $5/month so you're warned well before anything meaningful.

✔ Checkpoint: You have at least the Zero-spend budget + Free-Tier alerts turned on, both going to an email you check.

1 Create your AWS account

  1. Go to aws.amazon.com/free → Create a Free Account.
  2. Enter email, account name (e.g. Shifa Herbal Remedies), verify email, set a strong password.
  3. Add contact details and a card (used for identity + anything beyond free; your $100 credit is applied automatically).
  4. Choose Basic support — Free.
  5. At the top-right, set your region to Asia Pacific (Mumbai) ap-south-1 and keep it there for everything.
Free Plan vs Paid Plan? If AWS asks, the Paid Plan is recommended here — you still get the credits, plus the 12-month free allowances (needed for RDS). Your Step-0 budget alarm keeps you safe. (The Free Plan can't be charged at all but pauses after ~6 months/credits — fine only if you want a hard stop.)
✔ Checkpoint: You can log into the AWS Console and the region (top-right) says Mumbai.

2 Create the database (RDS for MySQL)

We create the database before the server so its address is ready. This is the "use RDS properly" part.

  1. Search bar → RDS → Create database.
  2. Creation method: Standard create.
  3. Engine: MySQL (version 8.0.x).
  4. Templates: pick Free tier ← this locks the free-eligible options for you.
  5. DB instance identifier: shifa-mysql.
  6. Master username: admin. Master password: set a strong one and save it.
  7. Instance configuration: db.t4g.micro (Free tier shows this).
  8. Storage: 20 GB gp3; turn OFF "Storage autoscaling" (so it can't silently grow past free).
  9. Connectivity: Don't connect to an EC2 yet (we'll allow it by security group). Public access = No (keep the DB private/safe).
  10. Additional configuration: Initial database name — leave blank (we create it in Step 6). Keep automated backups ON (7 days).
  11. Create database. It takes ~5–10 minutes. When ready, open it and copy the Endpoint (looks like shifa-mysql.xxxx.ap-south-1.rds.amazonaws.com) — you'll need it in Step 7.
Free-tier limits to respect: exactly one db.t4g.micro, Single-AZ (not Multi-AZ — that's paid), ≤ 20 GB storage, autoscaling off. The Free-tier template picks these for you; just don't change them. RDS is free for 750 hours/month for 12 months — one always-on DB fits.
✔ Checkpoint: RDS status is Available and you've copied its Endpoint address.

3 Launch the app server (EC2)

  1. Search bar → EC2 → Launch instance.
  2. Name: shifa-app.
  3. OS image: Ubuntu Server 24.04 LTS → then set Architecture = 64-bit (Arm). (Arm is required for the free t4g.)
  4. Instance type: t4g.small (2 vCPU / 2 GB — free until 31 Dec 2026).
  5. Key pair: Create new key pair → RSA → .pem → Download. Save it somewhere safe (e.g. C:\shifa\shifa-key.pem).
  6. Network settings → Edit → Create security group with 3 rules:
    • SSH (22) — Source My IP
    • HTTP (80) — Source Anywhere
    • HTTPS (443) — Source Anywhere
  7. Storage: 20 GB gp3.
  8. Launch instance. When it's Running, note the Public IPv4 address.

Give the server a fixed address (Elastic IP)

  1. EC2 left menu → Elastic IPs → Allocate Elastic IP address → Allocate.
  2. Select it → Actions → Associate → choose shifa-app → Associate. Use this IP as your site address.

Let the server reach the database

  1. Go to RDS → shifa-mysql → Connectivity & security → VPC security groups → click the DB's security group.
  2. Inbound rules → Edit → Add rule: Type MySQL/Aurora (3306), Source = the EC2's security group (start typing shifa-app / launch-wizard and pick it). Save.
This means "only my app server may talk to the database, privately." The database stays closed to the internet.
✔ Checkpoint: EC2 is Running with an Elastic IP, and the RDS security group allows port 3306 from the EC2's security group.

4 Connect to the server (SSH)

On your Windows PC, open PowerShell and run (replace the path and IP):

# one-time: lock down the key file so SSH will accept it
icacls "C:\shifa\shifa-key.pem" /inheritance:r /grant:r "$($env:USERNAME):(R)"

# log in (the username for Ubuntu is 'ubuntu')
ssh -i "C:\shifa\shifa-key.pem" ubuntu@YOUR_ELASTIC_IP

Type yes if asked to trust the server. You're now "inside" the server — the prompt shows ubuntu@....

5 Install Java, Nginx, MySQL client

Paste these on the server (one block):

sudo apt update && sudo apt -y upgrade
sudo apt -y install openjdk-21-jdk nginx mysql-client git unzip
java -version && nginx -v
We install the MySQL client only (to talk to RDS) — not a database server, because the database lives on RDS. We do not install Node/Maven here; the app is built on your PC (Step 8) because 2 GB RAM is too little to build Angular.

6 Create the database & user on RDS

From the server, connect to RDS using its Endpoint and the master password from Step 2:

mysql -h YOUR_RDS_ENDPOINT -u admin -p

Then paste this (change the password) and press Enter:

CREATE DATABASE IF NOT EXISTS shifa_dashboard CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'shifa'@'%' IDENTIFIED BY 'CHANGE_ME_STRONG_DB_PASSWORD';
GRANT ALL PRIVILEGES ON shifa_dashboard.* TO 'shifa'@'%';
FLUSH PRIVILEGES;
EXIT;
You don't create any tables by hand — the app runs Flyway on first start and builds everything (including the demo/test data seed) automatically.
✔ Checkpoint: The mysql -h ... -u admin -p command connected (proves EC2↔RDS networking works) and you created the shifa_dashboard database + shifa user.

7 Configure the app (env file)

sudo useradd -r -s /usr/sbin/nologin shifa || true
sudo mkdir -p /opt/shifa /var/www/shifa/admin /etc/shifa
sudo nano /etc/shifa/shifa.env

Paste this, filling in the real values, then save (Ctrl+O, Enter, Ctrl+X):

SPRING_PROFILES_ACTIVE=prod

# --- Database = your RDS endpoint (NOT localhost) ---
DB_HOST=YOUR_RDS_ENDPOINT
DB_PORT=3306
DB_NAME=shifa_dashboard
DB_USERNAME=shifa
DB_PASSWORD=CHANGE_ME_STRONG_DB_PASSWORD
# Connection pool sized for 50 concurrent users on db.t4g.micro (see Part B)
DB_POOL_SIZE=20

# --- Security ---
JWT_SECRET=PASTE_A_LONG_RANDOM_STRING
SEED_ADMIN_USERNAME=admin
SEED_ADMIN_PASSWORD=CHANGE_ME_ADMIN_PASSWORD
SEED_PACKING_USERNAME=packer
SEED_PACKING_PASSWORD=CHANGE_ME_PACKER_PASSWORD

# --- Integrations: keep mocked for now ---
COURIER_MODE=MOCK
WHATSAPP_MODE=MOCK
MAIL_MODE=MOCK

# --- Memory: DB is on RDS, so the app can use most of the 2 GB ---
JAVA_OPTS=-Xms512m -Xmx1300m

Generate the JWT_SECRET value by running openssl rand -base64 48 and pasting the output. Then lock the file:

sudo chmod 600 /etc/shifa/shifa.env

8 Build on your PC & upload

On your Windows PC (needs Java 21 + Maven + Node 20 installed):

# 1) build the backend
cd "c:\E Drive\Shifa-Software\backend"
mvn -DskipTests package

# 2) build the admin website (served at the site root)
cd "c:\E Drive\Shifa-Software\frontend"
npm ci
npx ng build admin --configuration production --base-href /

# 3) upload the jar, the website, and the service file
scp -i "C:\shifa\shifa-key.pem" "..\backend\target\shifa-oms-0.0.1-SNAPSHOT.jar" ubuntu@YOUR_ELASTIC_IP:/home/ubuntu/shifa-oms.jar
scp -i "C:\shifa\shifa-key.pem" -r ".\dist\admin\browser\*" ubuntu@YOUR_ELASTIC_IP:/home/ubuntu/admin-dist
scp -i "C:\shifa\shifa-key.pem" "..\deploy\shifa-oms.service" ubuntu@YOUR_ELASTIC_IP:/home/ubuntu/

Then, back on the server, put the files in place:

sudo cp ~/shifa-oms.jar /opt/shifa/shifa-oms.jar && sudo chown shifa:shifa /opt/shifa/shifa-oms.jar
sudo rm -rf /var/www/shifa/admin/* && sudo cp -r ~/admin-dist/* /var/www/shifa/admin/
sudo chown -R www-data:www-data /var/www/shifa
If the jar name differs, run ls ~/*.jar and use that name. The website folder must contain index.html (check ls ~/admin-dist).

9 Run the app as a service

sudo cp ~/shifa-oms.service /etc/systemd/system/shifa-oms.service
sudo systemctl daemon-reload
sudo systemctl enable --now shifa-oms
sudo journalctl -u shifa-oms -f

Watch the logs scroll. Success looks like "Started Application" and "Tomcat started on port 8080". Press Ctrl+C to stop watching. (Flyway will apply all migrations to RDS on this first run — it may take a minute.)

✔ Checkpoint: The log shows the app started with no database errors.

10 Set up Nginx (show the app at the web address)

sudo tee /etc/nginx/sites-available/shifa >/dev/null <<'NGINX'
server {
    listen 80;
    server_name _;
    client_max_body_size 15m;
    gzip on; gzip_types text/css application/javascript application/json image/svg+xml; gzip_min_length 1024;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }
    location = /api/admin/events {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_buffering off; proxy_cache off; proxy_read_timeout 3600s;
    }
    location / {
        root /var/www/shifa/admin;
        try_files $uri $uri/ /index.html;
    }
}
NGINX
sudo ln -sf /etc/nginx/sites-available/shifa /etc/nginx/sites-enabled/shifa
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

Now open http://YOUR_ELASTIC_IP/ in a browser — you should see the Shifa admin login. Log in as admin with your SEED_ADMIN_PASSWORD.

✔ Checkpoint: The login page loads and you can sign in. (Full demo logins: test-data-guide.html.)

B Make 50 concurrent users smooth

"50 concurrent users" doesn't mean 50 database queries at the exact same instant — each click is a query lasting a few milliseconds. The key setting is the connection pool: a small set of reusable database connections shared by everyone.

SettingValueWhy
DB_POOL_SIZE (in the env file)2020 shared connections easily serve 50 users doing short requests, and stay well under what a 1 GB RDS allows (~85 connections).
JAVA_OPTS heap-Xmx1300mDB is on RDS, so the app can use most of the EC2's 2 GB.
RDS instancedb.t4g.micro (free)Fine for 50 light users for the first several months. If dashboards feel slow under load, size up to db.t4g.small (paid, ~₹2,400/mo).
Data growing to millions of rows is not a problem. MySQL handles millions of well-indexed rows with fast queries; your tables are already indexed on the busy columns. Watch RAM/connections, not row count.

Keep an eye on it (free)

  • RDS → your DB → Monitoring tab: watch CPU, Freeable Memory, and DB Connections. If connections approach the limit or memory gets low during busy hours, raise the DB size.
  • The app also shows live health at /api/actuator/health if enabled.

C Backups & safety

  • RDS automated backups are ON (7 days) — AWS snapshots the database daily and lets you restore to any point in time. This is the big safety net; test a restore once so you trust it.
  • Manual snapshot before big changes: RDS → your DB → Actions → Take snapshot.
  • The app's own nightly dump writes to the EC2 disk (storage/); for off-server safety you can later point it at S3, or rely on RDS backups (recommended).

D Optional — Lambda automation (nearly free)

Lambda runs a tiny script on a schedule without a server. Its free tier (1,000,000 runs + 400,000 GB-seconds/month) means these cost essentially ₹0. Add them only if you want the convenience — the app works fine without them.

D1 · Weekly automatic database snapshot (recommended, simple)

RDS already backs up daily; this adds an extra named weekly snapshot you control.

  1. Search → Lambda → Create function → Author from scratch → Runtime Python 3.12 → name shifa-weekly-snapshot → Create.
  2. Paste this code and Deploy:
import boto3, datetime
rds = boto3.client('rds')
def handler(event, context):
    stamp = datetime.datetime.utcnow().strftime('%Y-%m-%d-%H%M')
    rds.create_db_snapshot(
        DBInstanceIdentifier='shifa-mysql',
        DBSnapshotIdentifier=f'shifa-weekly-{stamp}')
    return 'snapshot started'
  1. Set the handler to lambda_function.handler (Configuration → Runtime settings) if needed.
  2. Configuration → Permissions → click the role → attach a policy allowing rds:CreateDBSnapshot (add the AWS-managed AmazonRDSFullAccess for simplicity, or a small custom policy).
  3. Add a schedule: Add trigger → EventBridge (CloudWatch Events) → Create new rule → schedule expression rate(7 days) → Add.
The same pattern (EventBridge schedule → Lambda) is how you'd automate anything on a timer.

D2 · Daily 8 AM consolidated report to the admin

Every morning the admin gets an email summarising yesterday across the whole business — total sales, a per-salesperson breakdown, customers, and the order-status split. The report and email are built inside the app (endpoint POST /api/admin/reports/daily-digest/run). You have two easy ways to run it at 8 AM — pick one:

Easiest — let the app send it (no Lambda)

In /etc/shifa/shifa.env set the recipient, real email, and 8 AM schedule, then restart:

MAIL_MODE=SMTP
REPORT_DIGEST_TO=admin@yourcompany.com
REPORT_DIGEST_CRON=0 0 8 * * *
REPORT_DIGEST_ENABLED=true
sudo timedatectl set-timezone Asia/Kolkata   # so "8 AM" means IST
sudo systemctl restart shifa-oms

Or — an AWS Lambda triggers it at 8 AM IST (what you asked for)

First turn off the app's own schedule so the email isn't sent twice: set REPORT_DIGEST_ENABLED=false (keep MAIL_MODE=SMTP and REPORT_DIGEST_TO), restart. Then:

  1. Lambda → Create function → Python 3.12 → name shifa-daily-report. Add env vars APP_BASE (e.g. https://your-site), ADMIN_USER, ADMIN_PASS. Paste this code:
import os, json, urllib.request
def handler(event, context):
    base = os.environ['APP_BASE'].rstrip('/')
    login = urllib.request.Request(base + '/api/auth/login',
        data=json.dumps({'username': os.environ['ADMIN_USER'],
                         'password': os.environ['ADMIN_PASS']}).encode(),
        headers={'Content-Type':'application/json'}, method='POST')
    token = json.loads(urllib.request.urlopen(login, timeout=20).read())['accessToken']
    run = urllib.request.Request(base + '/api/admin/reports/daily-digest/run',
        headers={'Authorization':'Bearer ' + token}, method='POST')
    return urllib.request.urlopen(run, timeout=60).read().decode()
  1. Set timeout to ~30s. Add trigger → EventBridge → schedule expression cron(30 2 * * ? *) (= 02:30 UTC = 08:00 IST).
  2. Click Test once and confirm the admin gets the email.
Use one method, not both, or the admin gets two emails. The Lambda method sets REPORT_DIGEST_ENABLED=false exactly to avoid that. Keep ADMIN_PASS in the Lambda env or AWS Secrets Manager.
To actually send email you must set MAIL_MODE=SMTP plus the SMTP settings (e.g. a Gmail app password) in shifa.env — otherwise the report is only logged (MOCK mode).

D3 · Auto start/stop the server (only if you upsize)

On the free t4g.small, shutting the server at night saves nothing (it's already free). Only bother with a start/stop Lambda if you later move to a bigger paid instance. If so, two EventBridge schedules calling a Lambda that runs ec2.stop_instances / ec2.start_instances do the job. (Note: your database is on RDS and stays up, so night data is safe.)

❓ "Will I be charged?" — FAQ

How do I know I'm still free?Billing → Free Tier page shows your usage vs limits. Your Step-0 alerts email you before any charge.
What could accidentally cost money?Creating a 2nd EC2/RDS, choosing Multi-AZ, turning on storage autoscaling, a bigger instance size, or an unused Elastic IP left not attached. The Free-tier template + this guide avoid all of these.
When does "free" end?RDS + storage + IP free for 12 months from signup; EC2 t4g.small free until 31 Dec 2026. After that it's ~₹2,700/mo (credits cover the gap for a while).
Is my data safe if the server restarts?Yes — data lives on RDS, separate from the app server, and is backed up daily.

↑ Upgrading to zero-downtime later (optional, paid)

The free setup is one app server, so an app update pauses the site for ~30–60 seconds. When you're ready for true zero-downtime:

  1. Add a second EC2 and an Application Load Balancer (ALB) in front of both (~₹1,700/mo for the ALB + the 2nd server's hours beyond the 750 free).
  2. Deploy one server at a time — the load balancer keeps serving from the other, so users never see a pause.
  3. Optionally switch RDS to Multi-AZ (paid) so the database also survives a zone failure.

Nothing in the app changes — it's the same jar on both servers pointing at the same RDS. Detailed steps are in deployment-aws.html.
