A precise, follow-along runbook to stand up a new EC2 instance running the whole app (Angular Admin + Spring Boot API + self-hosted MySQL 8) loaded with your current data migrated from RDS. No RDS, no Lambda.

  • Time: ~60–90 min · Region: ap-south-1 (Mumbai) · Instance: t2.micro (Free Tier, $0)
  • Every step ends with a ✔ Verify — don't move on until it passes.
  • PC = run on your Windows PC (PowerShell). Everything else runs on the EC2 SSH shell.
  • Before starting: AWS login · your RDS endpoint + user + password · Java 21 + Maven & Node 20 + npm on your PC.

1 Build the app on your PC

⏱ 10–15 min · never build on the t2.micro (it will OOM)
PCcd "c:\E Drive\Shifa-Software"

# Backend JAR
mvn -f "backend/pom.xml" -DskipTests package

# Angular admin bundle
npm --prefix frontend ci
npm --prefix frontend run build:admin
Verify: backend\target\shifa-oms-0.0.1-SNAPSHOT.jar and frontend\dist\admin\browser\index.html exist.

Zip the bundle for upload:

PCCompress-Archive -Path "frontend\dist\admin\browser\*" -DestinationPath "admin.zip" -Force
Verify: admin.zip exists in the project root.

2 Launch the EC2 instance

⏱ 10 min
  1. Console → region Asia Pacific (Mumbai) ap-south-1 (top-right).
  2. EC2 → Instances → Launch instances.
  3. Name: shifa-oms.
  4. AMI: Ubuntu Server 22.04 LTS (64-bit x86, Free tier eligible).
  5. Instance type: t2.micro (Free tier eligible).
  6. Key pair: Create new → name shifa-key, RSA, .pem → Create. Save the downloaded file to C:\E Drive\aws-keys\shifa-key.pem (you can't re-download it).
  7. Network settings → Edit: Auto-assign public IP Enable; create security group shifa-sg with these inbound rules:
TypePortSource
SSH22My IP
HTTP80Anywhere 0.0.0.0/0
HTTPS443Anywhere 0.0.0.0/0
  1. Storage: root volume 30 GiB gp3.
  2. Launch instance.
Verify: shifa-oms shows Running and 2/2 checks passed (~2 min).

3 Give it a fixed public IP (Elastic IP)

⏱ 3 min
  1. EC2 → Network & Security → Elastic IPs → Allocate.
  2. Select it → Actions → Associate → Instance shifa-oms → Associate.
  3. Note this IP as <EIP> for the rest of the guide.
Verify: the instance's Public IPv4 equals <EIP>.
An Elastic IP is free while attached to a running instance. Keep exactly one, attached — an idle/unattached one bills ~$3.6/mo.

4 Connect via SSH from Windows

⏱ 5 min
PC# Lock down the key once (SSH refuses loose permissions)
icacls "C:\E Drive\aws-keys\shifa-key.pem" /inheritance:r
icacls "C:\E Drive\aws-keys\shifa-key.pem" /grant:r "%USERNAME%:R"

# Connect (Ubuntu default user is 'ubuntu')
ssh -i "C:\E Drive\aws-keys\shifa-key.pem" ubuntu@<EIP>
Verify: prompt becomes ubuntu@ip-...:~$ — you're on the server.

5 Prep the server: updates, swap, timezone

⏱ 10 min · on the instance
# 1. Update the OS
sudo apt update && sudo apt -y upgrade

# 2. Add 2 GB swap (critical on 1 GB RAM)
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
sudo sysctl vm.swappiness=10 && echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf

# 3. Timezone IST
sudo timedatectl set-timezone Asia/Kolkata
Verify: free -h shows Swap 2.0Gi; date shows IST.

6 Install Java 21, MySQL 8, Nginx

⏱ 10 min
sudo apt -y install openjdk-21-jre-headless mysql-server mysql-client nginx unzip
Verify: java -version (21), mysql --version (8.0), nginx -v all print versions.

7 Create the database + user, tune MySQL

⏱ 10 min
sudo mysql_secure_installation        # set a root password; answer Y to prompts

sudo mysql <<'SQL'
CREATE DATABASE IF NOT EXISTS shifa_dashboard CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'shifa'@'localhost' IDENTIFIED BY 'CHANGE_ME_DB_PASSWORD';
GRANT ALL PRIVILEGES ON shifa_dashboard.* TO 'shifa'@'localhost';
FLUSH PRIVILEGES;
SQL

sudo tee /etc/mysql/mysql.conf.d/shifa.cnf >/dev/null <<'CNF'
[mysqld]
innodb_buffer_pool_size = 128M
performance_schema = OFF
max_connections = 50
CNF
sudo systemctl restart mysql
Verify: mysql -u shifa -p -e "SHOW DATABASES;" lists shifa_dashboard.

8 Migrate your CURRENT data from RDS

⏱ 15 min · the dump includes flyway history, so no migrations re-run

8.1 Temporarily let the EC2 reach RDS

RDS console → your DB → its VPC security group → Inbound → Edit → Add rule: MySQL/Aurora 3306, Source = the shifa-sg security group. Save. (Removed again in Part 15.)

8.2 Dump from RDS & import locally (on the EC2)

mysqldump -h <RDS_ENDPOINT> -u <RDS_USERNAME> -p \
  --single-transaction --routines --triggers --set-gtid-purged=OFF \
  shifa_dashboard > ~/rds_dump.sql

mysql -u shifa -p shifa_dashboard < ~/rds_dump.sql
Verify — row counts should match RDS: 
mysql -u shifa -p shifa_dashboard -e \
 "SELECT (SELECT COUNT(*) FROM orders) orders, \
         (SELECT COUNT(*) FROM users) users, \
         (SELECT COUNT(*) FROM flyway_schema_history) migrations;"
EC2 can't reach RDS? Run the mysqldump from a machine that can (or your PC), then scp rds_dump.sql to the EC2 and import.

9 Upload the app artifacts

⏱ 10 min
PCscp -i "C:\E Drive\aws-keys\shifa-key.pem" "c:\E Drive\Shifa-Software\backend\target\shifa-oms-0.0.1-SNAPSHOT.jar" ubuntu@<EIP>:/home/ubuntu/shifa-oms.jar
PCscp -i "C:\E Drive\aws-keys\shifa-key.pem" "c:\E Drive\Shifa-Software\admin.zip" ubuntu@<EIP>:/home/ubuntu/

On the EC2:

sudo mkdir -p /opt/shifa /opt/shifa/storage /var/www/shifa/admin
sudo mv ~/shifa-oms.jar /opt/shifa/shifa-oms.jar
sudo unzip -o ~/admin.zip -d /var/www/shifa/admin
sudo useradd -r -s /usr/sbin/nologin shifa || true
sudo chown -R shifa:shifa /opt/shifa
Verify: ls -lh /opt/shifa/shifa-oms.jar and ls /var/www/shifa/admin/index.html exist.

10 Backend configuration file

⏱ 5 min
sudo mkdir -p /etc/shifa
sudo tee /etc/shifa/shifa.env >/dev/null <<'ENV'
SPRING_PROFILES_ACTIVE=prod
DB_HOST=localhost
DB_PORT=3306
DB_NAME=shifa_dashboard
DB_USERNAME=shifa
DB_PASSWORD=CHANGE_ME_DB_PASSWORD
DB_POOL_SIZE=8
JWT_SECRET=CHANGE_ME_LONG_RANDOM_SECRET
SEED_ADMIN_PASSWORD=CHANGE_ME_ADMIN_PW
SEED_PACKING_PASSWORD=CHANGE_ME_PACKER_PW
STORAGE_PROVIDER=LOCAL
COURIER_MODE=MOCK
WHATSAPP_MODE=MOCK
MAIL_MODE=MOCK
JAVA_OPTS=-Xms256m -Xmx512m
ENV
sudo chmod 600 /etc/shifa/shifa.env

openssl rand -base64 48                 # copy the output
sudo nano /etc/shifa/shifa.env          # paste JWT_SECRET, set DB_PASSWORD to match Part 7
Verify: sudo cat /etc/shifa/shifa.env shows a real DB_PASSWORD + long JWT_SECRET.
STORAGE_PROVIDER=LOCAL keeps files on the instance disk (simplest, $0). If your old app stored screenshots in S3, those stay in S3 and won't show under LOCAL — keep S3 + an EC2 instance role instead if you need them served.

11 Run the backend as a service

⏱ 10 min
sudo tee /etc/systemd/system/shifa-oms.service >/dev/null <<'UNIT'
[Unit]
Description=Shifa OMS (Spring Boot)
After=network.target mysql.service
Wants=mysql.service
[Service]
User=shifa
EnvironmentFile=/etc/shifa/shifa.env
ExecStart=/usr/bin/java $JAVA_OPTS -jar /opt/shifa/shifa-oms.jar
SuccessExitStatus=143
Restart=on-failure
RestartSec=5
[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable --now shifa-oms
sudo journalctl -u shifa-oms -f
Verify: log shows Tomcat started on port 8080 + Started ...Application. Ctrl-C to stop tailing, then curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:8080/api/auth/login returns an HTTP code (API is up).

12 Configure Nginx

⏱ 5 min · Admin at /, proxy /api/, SSE
sudo tee /etc/nginx/sites-available/shifa >/dev/null <<'NGINX'
server {
    listen 80;
    server_name _;
    client_max_body_size 15m;
    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }
    location = /api/admin/events {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Connection '';
        proxy_buffering off; proxy_cache off; proxy_read_timeout 3600s;
    }
    location / {
        root /var/www/shifa/admin;
        try_files $uri $uri/ /index.html;
    }
}
NGINX
sudo ln -sf /etc/nginx/sites-available/shifa /etc/nginx/sites-enabled/shifa
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
Verify: open http://<EIP>/ → Admin login loads; log in as a migrated user → live data shows.

13 Free HTTPS with a hostname

⏱ 10 min · sslip.io, no domain purchase
sudo apt -y install certbot python3-certbot-nginx
# EIP 13.234.56.78  ->  13-234-56-78.sslip.io
sudo sed -i 's/server_name _;/server_name <EIP-with-dashes>.sslip.io;/' /etc/nginx/sites-available/shifa
sudo systemctl reload nginx
sudo certbot --nginx -d <EIP-with-dashes>.sslip.io --redirect --agree-tos -m you@example.com --no-eff-email
Verify: https://<EIP-with-dashes>.sslip.io/ loads with a padlock; login works.
Own a domain? Point an A record to <EIP> and run certbot with -d yourdomain.com.

14 Smoke test the full flow

⏱ 10 min
  • Dashboard loads with your real numbers.
  • Orders list shows migrated orders.
  • Create a test order as a salesperson → appears & can be approved.
  • Approve it → label generated (Print Label works).
  • A report / analytics page renders.
  • Log out / log back in.
Verify: all pass → cutover successful.

15 Lock things back down

⏱ 5 min
  1. RDS security group → delete the temporary 3306 from shifa-sg inbound rule.
  2. rm ~/rds_dump.sql on the EC2.
Verify: app still works (now using local MySQL, not RDS).

16 Nightly backups

⏱ 5 min
sudo tee /opt/shifa/backup.sh >/dev/null <<'BK'
#!/usr/bin/env bash
set -e
STAMP=$(date +%F); mkdir -p /opt/shifa/backups
mysqldump -u shifa -p"$DB_PASSWORD" --single-transaction shifa_dashboard | gzip > /opt/shifa/backups/db-$STAMP.sql.gz
find /opt/shifa/backups -name 'db-*.sql.gz' -mtime +14 -delete
BK
sudo chmod +x /opt/shifa/backup.sh
( sudo crontab -l 2>/dev/null; echo "0 2 * * * DB_PASSWORD=CHANGE_ME_DB_PASSWORD /opt/shifa/backup.sh" ) | sudo crontab -

sudo DB_PASSWORD=CHANGE_ME_DB_PASSWORD /opt/shifa/backup.sh   # run once now
ls -lh /opt/shifa/backups/
Verify: a db-<date>.sql.gz exists. Test a restore into a scratch DB at least once.

17 Retire RDS to stop the bill

⏱ after 2–3 confident days
  1. RDS → your DB → Actions → Take snapshot (shifa-final-pre-delete).
  2. RDS → Actions → Delete (you already have a snapshot) → confirm. Stops ~$7.35/mo.
  3. EC2 → Elastic IPs → release any unattached IPs (keep the one on shifa-oms).
Verify: RDS shows no running instance; Billing → Cost Explorer trends down next day.

18 Operations cheat-sheet

Service control / logs

sudo systemctl status shifa-oms
sudo journalctl -u shifa-oms -f
sudo systemctl restart shifa-oms
sudo tail -f /var/log/nginx/error.log

Redeploy after code changes (build on PC first)

PCscp -i "C:\E Drive\aws-keys\shifa-key.pem" "c:\E Drive\Shifa-Software\backend\target\shifa-oms-0.0.1-SNAPSHOT.jar" ubuntu@<EIP>:/home/ubuntu/shifa-oms.jar
PCCompress-Archive -Path "frontend\dist\admin\browser\*" -DestinationPath "admin.zip" -Force
PCscp -i "C:\E Drive\aws-keys\shifa-key.pem" "c:\E Drive\Shifa-Software\admin.zip" ubuntu@<EIP>:/home/ubuntu/
# on the EC2:
sudo mv ~/shifa-oms.jar /opt/shifa/shifa-oms.jar
sudo rm -rf /var/www/shifa/admin/* && sudo unzip -o ~/admin.zip -d /var/www/shifa/admin
sudo chown -R shifa:shifa /opt/shifa
sudo systemctl restart shifa-oms && sudo systemctl reload nginx

Schema changes: add a new Flyway file V39__...sql before building — it applies on restart. Data + env are never touched by a redeploy.

If reports feel slow → resize to t3.small (2 GB), ~3 min

  1. EC2 → shifa-oms → Instance state → Stop (wait for Stopped).
  2. Actions → Instance settings → Change instance type → t3.small → Apply.
  3. Instance state → Start. (Elastic IP stays — same URL.)
  4. Bump limits: JAVA_OPTS=-Xms512m -Xmx1g, DB_POOL_SIZE=12, MySQL innodb_buffer_pool_size = 512M; then restart mysql & shifa-oms.

⚠ Troubleshooting

SymptomFix
Can't reach http://<EIP>/Security group allows 80/443 (Part 2); instance Running; sudo systemctl status nginx.
502 Bad GatewayBackend down: sudo journalctl -u shifa-oms -e. Usually a DB password mismatch in /etc/shifa/shifa.env.
Backend won't start, DB errorDB_PASSWORD must match Part 7; mysql -u shifa -p should connect.
App starts, no/blank dataRDS import (Part 8) didn't run or counts were 0 — re-import & re-check counts.
Flyway "validate" error on bootMigrated schema differs from the JAR's migrations — deploy the matching JAR / correct dump.
Out of memory / killedConfirm 2 GB swap (free -h); keep -Xmx512m; if persistent, resize to t3.small (Part 18).
SSH refusedFix key perms (Part 4 icacls); SSH-22 source = your IP; ISP IP changed → update the SG rule.
SSE dashboard not liveEnsure the location = /api/admin/events block is present and nginx -t passes.
