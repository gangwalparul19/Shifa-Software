The key idea about "concurrent users": 100 people logged in is not 100 requests happening at the same instant. In a dashboard like this, people spend most of their time reading and typing. At any moment only a handful are actually clicking. So a modest server serves a surprisingly large team comfortably.

4 What needs to increase as you grow

You don't upgrade everything at once. Things get raised in this order, as the team grows:

  1. Nothing (0 – 100 users): the free server already handles this. We just fine-tune settings — database connection pool, memory limits, gzip compression.
  2. Add backups (any size): the first real spend — automatic daily database + file backups so nothing is ever lost. Small, worth it early.
  3. More RAM & CPU (100 – 300 users): give the app and database more memory so data stays fast in memory. This is a single "resize the server" step — no code changes.
  4. Separate the database (300 – 500 users): move MySQL onto its own machine so a heavy report can't slow down order entry.
  5. Add a second app server + load balancer (500 – 1000+): two copies of the app share the load, and if one restarts the site stays up. This is the "always-on, large-team" setup.
  6. Bigger object storage (any time): file storage grows automatically and is billed only for what you use — no upfront jump.

6 Storage — the "unlimited files" question

Two kinds of storage matter, and they cost very differently:

🗃️ Database storage
Orders, customers, leads, invoices as data rows. Grows slowly — even years of orders stay small (a few GB). Effectively a non-issue on your plan.
📦 Object storage (files)
Invoice PDFs, shipping labels, payment screenshots, staff ID photos. This is where "space" is used. It grows on demand — you never pre-buy a fixed amount.
About "unlimited storage" hosting offers: those are shared PHP website plans (for WordPress-type sites) and cannot run your Java application at all. Their "unlimited" also comes with fair-use limits. For your app, the right pattern is pay-only-for-what-you-use object storage, which is genuinely cheap and scales without limit.

7 Our recommendation for you

  • ✅ Start on the free Oracle Cloud server (4 CPU / 24 GB). It comfortably runs the whole business for your stated 100 concurrent users at ₹0/month.
  • ✅ Add automatic daily backups early (a few hundred rupees) — the one thing worth paying for from day one, so business data is never at risk.
  • 📈 Only upgrade when you feel it. Growing past ~250–300 active users is a simple "resize the server" step, with no changes to the software.
  • 📦 Keep files in object storage. It's the true "unlimited storage" answer — cheap, safe, and grows on its own (first 10 GB free).
  • 🛡️ Single server = one tradeoff: if it restarts, the site is briefly down. That's fine for internal use; the "Scale" plan (two app servers) removes even that when the business needs always-on.
Bottom line: for 100 concurrent users you can launch at ₹0/month. A safe, comfortable setup with backups is roughly ₹1,500 – ₹2,500/month. You would only reach ₹6,000+ once you're serving several hundred simultaneous users — a very good problem to have.
