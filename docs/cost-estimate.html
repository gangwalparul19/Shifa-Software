4. Server sizing & capacity (~50 users)

The workload is light (form entry, 10-row paginated lists, dashboards). Data volume is a non-issue — ~30k orders in 6 months is trivial for MySQL 8 with the existing indexes (sub-second queries). The only real constraint on the smallest box is RAM, because the JVM and MySQL share it. For ~50 users, t4g.medium (4 GB) is the sweet spot; a fully-free alternative is t4g.small + RDS db.t4g.micro (DB on its own instance, both free 12 months). db engine capacity is not the concern — RAM headroom is.

5. Nightly power-down (00:30–05:30 IST) — what to watch

PointDetail
Compute saving~19 h/day ≈ 578 h/mo vs 730 h — ~21% off compute on a paid instance. (No saving on the free t4g.small.)
⚠️ Scheduled jobs at 02:00The app runs the DB backup and insights computation at 02:00 — inside the downtime. Move these out of the window (e.g. backup 23:45, insights 23:50, daily digest 06:00) via the env cron settings, or run them on Lambda (§6).
Stable URLUse an Elastic IP — the auto-assigned public IP changes on every stop/start. (EIP ~₹350/mo after the 12-month free IPv4 window.)
AutomationAutomate stop (00:30) / start (05:30) with EventBridge Scheduler + a tiny Lambda or AWS Instance Scheduler — no manual work.
Data safetyMySQL data lives on the EBS disk and persists across stop/start — no data loss.

6. Optional — AWS Lambda for reports & automation

Lambda + EventBridge Scheduler is a clean, near-free way to run scheduled work independently of the EC2 (so it keeps working during the nightly power-down). Good uses:

  • EC2 stop/start automation (00:30 / 05:30) — the simplest, highest-value Lambda here.
  • Scheduled reports (daily / weekly / monthly) emailed as PDF/Excel, and the nightly insights + DB backup — offloaded from the app box.
Dependency: night-time Lambda jobs need the database while the EC2 is off, so the DB must be always-on → use RDS (the t4g.small + RDS option), not MySQL on the stopped EC2. Also, today's report/insight logic lives inside the Spring Boot app, so a Lambda would either package that Java code or call an API — some engineering effort.
Cost: Lambda's always-free tier (1M requests + 400,000 GB-seconds/month) means a handful of scheduled runs per day is effectively ₹0 forever. Recommendation: for now, keep reports/insights inside the app and just move the cron times out of the downtime window (₹0, no new moving parts). Adopt RDS + Lambda later if you want true night-time jobs or heavy off-box report generation.
