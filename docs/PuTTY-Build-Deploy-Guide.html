1 Install the PuTTY tools

You need three programs from the PuTTY suite (all included in the standard installer from putty.org → the MSI installer):

  • putty.exe — the SSH terminal (run commands on the server).
  • puttygen.exe — converts the AWS .pem key into PuTTY's .ppk format.
  • pscp.exe — copies files from your PC to the server (PuTTY's version of scp).
Verify: you can find PuTTY, PuTTYgen and PSCP in the Start menu / install folder (usually C:\Program Files\PuTTY\).
Installing the full MSI puts pscp.exe on your PATH so you can run pscp from any PowerShell/CMD window. If not, run it with its full path: "C:\Program Files\PuTTY\pscp.exe".

2 Convert the .pem key to .ppk (PuTTYgen)

PuTTY doesn't use AWS's .pem directly — convert it once:

  1. Open PuTTYgen.
  2. Menu Conversions → Import key.
  3. Select C:\Users\Parul\Downloads\shifa-admin.pem → Open.
  4. (Optional) set a passphrase for extra security, or leave blank for convenience.
  5. Click Save private key → save as C:\Users\Parul\Downloads\shifa-admin.ppk (confirm "save without a passphrase" if you left it blank).
Verify: shifa-admin.ppk now exists next to your .pem.
Keep both key files private. Never share, commit, or email them — anyone with the key can log into your server.

3 Configure & save a PuTTY session

  1. Open PuTTY.
  2. Session screen → Host Name: ubuntu@13.234.22.207 · Port: 22 · Connection type: SSH.
  3. Left tree → Connection → SSH → Auth → Credentials → Private key file for authentication → Browse → pick shifa-admin.ppk.
  4. (Optional) Connection → Data → Auto-login username: ubuntu.
  5. (Optional, avoids idle disconnects) Connection → Seconds between keepalives: 30.
  6. Go back to Session → under Saved Sessions type shifa-oms → Save.
Verify: shifa-oms appears in the Saved Sessions list — next time just double-click it.

4 Connect (open the SSH window)

  1. In PuTTY, select the shifa-oms saved session → Open (or double-click it).
  2. First time only: a security alert about the host key appears → click Accept.
  3. If you set a passphrase on the key, enter it now.
Verify: you see the prompt ubuntu@ip-172-31-3-104:~$ — you're on the server.

5 Build the app on your PC

PC Open PowerShell in the project root and build both artifacts. Always build on your PC — never on the small instance.

PCcd "c:\E Drive\Shifa-Software"

REM 1) Backend JAR
mvn -f "backend/pom.xml" -DskipTests package

REM 2) Angular admin bundle
npm --prefix frontend ci
npm --prefix frontend run build:admin

REM 3) Zip the admin bundle for upload (PowerShell)
Compress-Archive -Path "frontend\dist\admin\browser\*" -DestinationPath "admin.zip" -Force
Verify: backend\target\shifa-oms-0.0.1-SNAPSHOT.jar and admin.zip both exist.
Use npm --prefix frontend ci the first time (clean install); afterwards npm --prefix frontend install is fine and faster.

6 Upload the build with PSCP

PC PSCP is PuTTY's file-copy tool. It uses the .ppk key. Run from a PowerShell/CMD window on your PC:

PCREM Upload the JAR (renamed to shifa-oms.jar on the server)
pscp -i "C:\Users\Parul\Downloads\shifa-admin.ppk" "c:\E Drive\Shifa-Software\backend\target\shifa-oms-0.0.1-SNAPSHOT.jar" ubuntu@13.234.22.207:/home/ubuntu/shifa-oms.jar

REM Upload the admin bundle zip
pscp -i "C:\Users\Parul\Downloads\shifa-admin.ppk" "c:\E Drive\Shifa-Software\admin.zip" ubuntu@13.234.22.207:/home/ubuntu/
Verify: PSCP prints a progress bar reaching 100% for each file with no error.
If pscp isn't recognised, use the full path: "C:\Program Files\PuTTY\pscp.exe" -i .... If it prompts about the host key the first time, type y.

7 Deploy on the instance

EC2 In your PuTTY SSH window, swap in the new files and restart. This never touches the database or the env file.

EC2REM Put the new JAR in place
sudo mv ~/shifa-oms.jar /opt/shifa/shifa-oms.jar

REM Replace the admin web files
sudo rm -rf /var/www/shifa/admin/*
sudo unzip -o ~/admin.zip -d /var/www/shifa/admin

REM Fix ownership, then restart backend + reload web
sudo chown -R shifa:shifa /opt/shifa
sudo systemctl restart shifa-oms
sudo systemctl reload nginx
Verify: sudo systemctl status shifa-oms shows active (running), and the app at http://13.234.22.207/ shows your changes after a refresh (Ctrl+F5).
Database/schema changes deploy automatically: add a new Flyway file V39__...sql before building — it applies on the next restart. Your live data is preserved.

8 Start / stop / check the server

EC2 The backend runs as the shifa-oms systemd service (auto-starts on boot).

EC2REM Start / stop / restart the backend
sudo systemctl start shifa-oms
sudo systemctl stop shifa-oms
sudo systemctl restart shifa-oms

REM Status + live logs (Ctrl+C to stop watching)
sudo systemctl status shifa-oms
sudo journalctl -u shifa-oms -f

REM Make sure it starts automatically on reboot
sudo systemctl enable shifa-oms

Web server (Nginx) & database (MySQL)

EC2sudo systemctl reload nginx      REM apply nginx config changes
sudo systemctl restart nginx     REM full restart
sudo systemctl status nginx

sudo systemctl status mysql      REM database service
sudo tail -f /var/log/nginx/error.log
Verify a healthy start: the logs show Tomcat started on port 8080 and Started ...Application.

⚠ Troubleshooting

SymptomFix
PuTTY: "server refused our key" / can't log inYou're using the .pem instead of the .ppk. Point PuTTY (Connection → SSH → Auth) at shifa-admin.ppk from Part 2.
PuTTY: "Network error: Connection timed out"Instance not running, wrong IP, or security group doesn't allow SSH (22) from your IP. Check EC2 console.
pscp not recognisedUse the full path "C:\Program Files\PuTTY\pscp.exe", or add PuTTY to your PATH.
PSCP "Fatal: Received unexpected ..." / auth failsMake sure you pass the .ppk with -i, and the username is ubuntu.
App didn't update after deployHard-refresh the browser (Ctrl+F5). Confirm the JAR/zip actually uploaded (PSCP hit 100%) and you restarted the service.
502 Bad GatewayBackend down: sudo journalctl -u shifa-oms -e. Often a DB password mismatch in /etc/shifa/shifa.env.
Backend won't startCheck logs: sudo journalctl -u shifa-oms -n 50 --no-pager. Look for the first ERROR line.
IP changed after stop/startElastic IP should stay attached. If it changed, update 13.234.22.207 in the PuTTY session and the PSCP commands.
