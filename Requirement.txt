1. User Roles  
Admin, Accountant, Salesperson, Packing Department, Customer

2. Order Entry Module  
Salesperson Workflow:
1. Customer enquiry receive on instagram or whatsapp. Then the team share the QR for payment and collect the amount.
2. Customer confirm the payment via screenhsot so that needs to be implemneetd and added onto the database for each record.

When salesperson Punch the order the he enter below details at present:
- Customer Details: Name, Mobile Number, Complete Shipping Address
- Product Details: Item selection + Quantity per item  
- Rate Flexibility: Every item rate is editable. System will show the default sale pricebut the salesperson  can change the rate
- Payment Collection:
    - Total Order Amount: Items + quantity auto calculate amount.
    - Amount Received: Customer payed the amountand salesperson add that
    - Payment Screenshot: IF payment paid (amount received) > 0 then salesperson has to upload screenshot (mandatory)
    - Remaining Amount: System automatically calculate which is = Total Amount - Amount Received
    - Payment Status: System auto set 
        - Amount Received = 0 → Status: COD
        - Amount Received < Total Amount → Status: Partially Paid + COD Amount (yet to take from client)
        - Amount Received = Total Amount → Status: Fully Paid
- Payment Proof: Customer payment screenshot should be added on each order when payment receive 

Order Post-Submission Flow:
1. Admin Approval Queue: Once the Order is punched status is changed to  "Pending Admin Approval"
2. Admin Verification: Admin will check order - Payment screenshot, Items, Applied rates, Total Amount, Paid Amount, COD Amount, Payment Status
3. Approve/Reject: Admin will approve or reject the order with reason
4. Company Label Generation: Once order is Approved, packing label should be generated with Order ID + Barcode, Customer details, Item list, COD Amount: ₹XXX if its COD.
5. Packing Department: Once the Label is printed, Packing Department will pack item, label will be attcahed to the parcel and a Barcode scan. Once the barcode is scanned by the packaging tean, order status should be changed to "Packed"and Admin will get real-time notification
6. Courier Integration: Once status "Packed" is set, courier company API will be hit and the shipping label + AWB number will be generateed with remaining COD amount
7. Customer WhatsApp Notification: Once the courier company pickup the parcel, status will be changed to "Dispatched/In Transit", customer will be notified on WhatsApp with:
      - Order Status: "Our order with orderid-xxx is been dispatched parcel"
      - Courier Company Name
      - Tracking ID/AWB Number
      - Tracking Link: Courier company official tracking website direct link
      - COD Amount: If COD then remaining amount to be payed
      - Estimated Delivery Date
8. Live Order Tracking: Courier API will update delivery status in our application as - In Transit, Out for Delivery, Delivered, RTO, Lost/Damaged. 
This all status, Admin dashboard will display on real-time. Customer will also see major status update and WhatsApp message will be send
9. Courier COD Settlement & Loss Management: 
      - Prepaid Orders: Once the Status is set as "Delivered", order will automatically "Closed" and the Customer outstanding will be NIL.
      - COD Orders -  Once the Status is set as Delivered, Once the status is changed to "Delivered" from Courier Service API, our system will change then order status to "COD Collected". Customer outstanding will be set as NIL and for us, status will be changed to "Courier Company Receivable" as this amount we need to collect from Courier company.
      - COD Orders - If the Order is Returned or Not delivered, Status will be "RTO" Once it is RTO COD amount automatically will be cancel. Customer outstanding will be set as NIL
      - Shipment Loss/Damage by Courier: If courier company API set staus as  "Lost", "Damaged" or "Missing", our system automatically:
          - Order status "Redispatch"
          - Net Order Amount will be settled by courier company so status will be set as "Claim Receivable"
          - Admin will get notification that AWB# claim need to be filed.
          - Customer outstanding for that order would be cleared as the liability is of courier company
          - Whether the order is Prepaidor COD, in both case, full amount courier company will bear.
		  
      - COD Reconciliation Dashboard: Admin should get then COD + Loss settlement report seperately:
          - Which order is Delivered + COD amount for that order
          - How much amount to collect from Courier company for COD
          - How much amount to collect from Courier company for "Lost Shipment"
          - Which order is prepaid and which is COD
          - Which COD order is delivered but courier company not yet transffered the amount to us.
          - RTO orders, COD amount will automatically cancel.

- Sales Graph: Day-wise, Week-wise, Monthly view with comparison line. Previous period se % growth/decline should be shown
- Live Stats: Real-time order count, Today's collection, Total COD Amount to Collect from Courier, Total Loss Amount to Claim from Courier
- Activity Cards: Fulfill Orders, Capture Payments, RTO Alerts, WhatsApp Notifications Sent, COD Settlement Pending, Courier Claims Pending
